**Minor findings, none blocking:**

- **Stage label can mislead on a crashed build.** `JSON.parse(built.stdout)` runs under the metadata-validation stage before the exit-status check (`iphone-testflight.mjs:54-59`). A build that times out or dies with non-JSON output reports "failed at EAS build metadata validation" instead of "EAS production build". Still fails safely. The preview helper has the same ordering.
- **Two 340-minute subprocess timeouts inside one 360-minute job.** Build then submit run sequentially, so a pathological build could push submit past the job limit and lose the summary. Realistic build times make this theoretical.
- **Docs disagree on where EXPO_TOKEN lives.** RELEASING.md line 5 says repository secret; CI_CD_SETUP_GUIDE.md step 3 and the preview section say production environment secret. `secrets.EXPO_TOKEN` resolves either, so behavior is unaffected, but the operator will read two different instructions.
- **GITHUB_TOKEN is passed into the EAS child process** along with the rest of `env`. Pre-existing pattern in release.mjs and iphone-preview.mjs, not a regression.
